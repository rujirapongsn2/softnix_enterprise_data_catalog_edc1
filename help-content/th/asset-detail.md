## หน้านี้คืออะไร {#what}

หน้า **รายละเอียดชุดข้อมูล** รวมทุกอย่างที่ EDC รู้เกี่ยวกับชุดข้อมูลหนึ่งชุด เช่น `lakehouse.gold.customer_360` ส่วนหัวแสดงชื่อเชิงธุรกิจ ป้ายสถานะ (Certified, Authoritative source, Critical, PII) path ประเภท โดเมน และชั้นความลับ พร้อม **Rating**, **Data quality**, **Freshness** และ **Rows** ส่วนรายละเอียดอยู่ในแท็บด้านล่าง

## วัตถุประสงค์และเป้าหมาย {#purpose}

- ช่วยตัดสินใจว่าข้อมูลชุดนี้เหมาะกับงานของคุณและเชื่อถือได้หรือไม่
- รู้ว่าควรติดต่อใคร (Owner, Steward, Custodian, DPO) และนำข้อมูลไปใช้ทำอะไรได้บ้าง
- เห็นผลกระทบทั้งต้นทางและปลายทางก่อนเปลี่ยนแปลงอะไร

## ใครใช้หน้านี้ {#who}

ทุกคนที่ทำงานกับข้อมูล ผู้ใช้ข้อมูลเปิดอ่านและขอสิทธิ์ Steward และ Owner แก้ไข metadata เชิงธุรกิจและรับรองข้อมูล Custodian ตรวจ lineage และ contract ส่วนผู้ตรวจสอบดูได้อย่างเดียว

## วิธีใช้งาน {#how}

1. **ภาพรวม (Overview)**: อ่านคำอธิบาย คำศัพท์และแท็กที่ผูกไว้ คุณลักษณะเชิงธุรกิจ (วัตถุประสงค์, ความถี่อัปเดต, SLA ความสดใหม่, ระยะเวลาเก็บ, ฐานทางกฎหมาย) metadata เชิงเทคนิค ผู้เกี่ยวข้อง สรุป DQ และ **Certification readiness**
2. **คอลัมน์ (Columns)**: กรองแบบ All, PII, CDE หรือ Undocumented แล้วคลิกคอลัมน์เพื่อเปิดแผงรายละเอียด ซึ่งแสดงชนิดข้อมูล คำศัพท์ ชั้นความลับ สถานะ PII และ profile (null % / distinct %)
3. **สายข้อมูล (Lineage)**: ดูแหล่งต้นทางและผู้ใช้ปลายทาง ใช้วิเคราะห์ผลกระทบ (impact analysis)
4. **สัญญาข้อมูล (Contract)**: เทียบ schema ที่ตกลงไว้ใน data contract (ODCS) กับ schema จริงที่ดึงมา การเปลี่ยนแปลงแบบ breaking จะขึ้นสีแดง และดูสถานะ SLA/SLO กับผู้ใช้ที่ได้รับผลกระทบได้
5. **คุณภาพข้อมูล (Data Quality)**: ดูคะแนนแยกตามมิติ แนวโน้มคะแนน กฎ และกฎที่ AI แนะนำ
6. **สิทธิ์การเข้าถึง (Access)**: ดูว่าใครมีสิทธิ์ คอลัมน์ไหนถูก mask สิทธิ์ของคุณเอง และนโยบายที่ใช้กับชุดข้อมูลนี้
7. **ประวัติ (History)**: ดู audit trail และเวอร์ชันของ schema

## ฟิลด์และตัวชี้วัดสำคัญ {#fields}

- **Certification readiness**: มี Owner, มี Steward, มีคำอธิบาย, มีชั้นความลับ, ผูกคำศัพท์แล้ว และยืนยัน PII แล้ว ชุดข้อมูลสำคัญต้องผ่านครบทุกข้อก่อน Owner จะรับรองได้ (CDMC C2)
- **CDE**: Critical Data Element คือคอลัมน์สำคัญที่ใช้กฎคุณภาพเข้มกว่าปกติ
- **ป้าย PII ที่มี "?"**: ระบบจัดประเภทอัตโนมัติเสนอไว้ และยังรอ Steward ยืนยัน
- **สถานะ Contract**: Compliant หรือ **Violated** ถ้ามี breaking change ระบบจะกักการเผยแพร่ไปชั้น Gold ไว้ก่อน (quarantine)
- **Freshness SLA**: อายุข้อมูลสูงสุดที่ยอมรับได้ เช่น ไม่เกิน 26 ชั่วโมง

## งานที่ทำบ่อย {#tasks}

- **ขอสิทธิ์ (Request access)**: ระบุวัตถุประสงค์ (บังคับ) สิทธิ์ ระยะเวลา (30/90/180 วัน) และคอลัมน์ ถ้าเลือกคอลัมน์ PII จะมีขั้นตอน DPO เพิ่ม: ส่งคำขอ → Data Owner → DPO (PII) → ให้สิทธิ์ใน Lakehouse
- **แจ้งปัญหา (Report issue)**: ระบุหัวข้อ มิติคุณภาพ ความรุนแรง และรายละเอียด ระบบจะส่งเรื่องให้ Steward อัตโนมัติ
- **ติดตาม (Follow)** เพื่อรับแจ้งเตือนเมื่อมีการเปลี่ยนแปลง และใช้ **พูดคุย (Discussion)** เพื่อถาม ให้คะแนน หรือตอบกลับ
- **Explain with AI**: ให้ Softnix อธิบายตารางนี้ในภาษาธุรกิจ
- สำหรับ Steward: **Edit** หรือ **Regenerate** คำอธิบาย, ยอมรับหรือปฏิเสธร่างจาก AI, ยืนยันหรือปฏิเสธ PII ที่ระบบเสนอ
- **เปิดใน SQL editor**: เปิดตารางใน Lakehouse (Trino)

## เคล็ดลับและคำถามที่พบบ่อย {#tips}

- ข้อความ **"You can see metadata but not query data"** แปลว่าคุณดู metadata ได้ แต่ต้องขอสิทธิ์ก่อนจึงจะ query ข้อมูลได้
- คอลัมน์ PII ที่ไม่ได้เลือกตอนขอสิทธิ์จะยังถูก mask อยู่ แม้คำขอจะได้รับอนุมัติแล้ว
- สิทธิ์มีวันหมดอายุ และระบบจะเพิกถอนให้อัตโนมัติเมื่อครบกำหนด
- การแก้ไขที่ใช้ AI ช่วยจะถูกบันทึกใน audit trail ว่าเป็น AI-assisted
